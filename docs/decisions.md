# 第一阶段的决定

2026-11-06 和 lroel 一起定下，详细的备选方案和取舍见方案文档。

| 编号 | 决定 | 要点 |
| --- | --- | --- |
| 范围 | 第一阶段只做 Mac ↔ Mac，Intel 和 Apple Silicon 都支持 | Linux、Wayland、Windows、浏览器、移动端放到后续阶段 |
| D1 | 服务端：平台无关的 C++20 核心（`core/`）+ Objective-C++ 的 Mac 外壳 | 核心以后给 Linux 复用；认证解析代码配 fuzz |
| D2 | 客户端：原生 AppKit | 在 rdaccel 的 `examples/remote_mac` 基础上扩展；界面逻辑尽量放进核心 |
| D3 | 控制连接：TLS 1.3 + 首次确认证书指纹 | M0 支持系统账号密码和配对码；每次会话生成新的 rdaccel 密钥（[协议](protocol.md)） |
| D4 | TCP 4100 控制 + rdaccel UDP 画面，UDP 不通退回 rdaccel TCP | 换网络不断线以后靠 rdaccel 加连接 ID |
| D5 | M0 只控制已登录用户的物理桌面，M1 补登录窗口和锁屏 | 无显示器的虚拟屏放到 M2 实验 |
| 系统版本 | 最低 macOS 12.3 | 为了 2016 款 Intel MacBook Pro；rdaccel 从 1.0.1 起支持（[rdaccel#39](https://github.com/lroel9527/rdaccel/issues/39)），rdmachine 的子模块现在用 1.9.2 |
| 签名 | 暂无 Apple Developer 账号，M0 用本机证书签名自测 | 不做公证分发；用 `packaging/macos/create-signing-identity.sh` 建一张固定的自签证书，应用标识固定为 `org.rdmachine.server` / `org.rdmachine.client`，重新编译后权限不丢 |
| 桌面 | 客户端请求桌面，服务端建虚拟屏（2026-11-10） | D5 里“虚拟屏放到 M2”提前：HiDPI 只能在被控端解决，客户端缩放补不回来。客户端只说要什么（像素宽高 + 每点像素数），服务端用 `CGVirtualDisplay` 建一块同样规格的显示器，设为主屏，真实显示器镜像它，会话结束后恢复；没有显示器的 Mac 也因此能用。`CGVirtualDisplay` 没有公开头文件（BetterDisplay、DeskPad 等同样在用），按类名查找，系统没有或创建失败时退回共享真实显示器、客户端缩放。边界：规格和消息在 `core/`（`desktop.h`），建屏在 `session/`（`VirtualDesktop`）；rdaccel 只补了通用的两处（1.4.3：缩放系数从显示模式读、注入坐标跟随模式变化）。细节见[协议](protocol.md)的“请求桌面” |
| 文字模式 | 省流量：文字清晰、立刻到，客户端决定开不开（2026-11-10） | 目的是少花流量（按流量计费的链路），不是链路慢。优先级（lroel，2026-11-10）：先保障体验，再去省流量。体验要和普通模式一样（运动时整体走视频，不逐块决定；视频、滚动不降帧率），省在看不出来的地方：静止和打字的文字减色后用专门的编码，省 3–7 倍，滚动和拖窗省三到六成，影片基本不省。最初按“链路极慢、慢慢补”做，实际使用中占位色块停留太久，rdaccel 1.7 改成现在这样；链路真的慢时才退到“先保持旧内容、之后补上”。由客户端请求（View → Data Saver，记住选择；`session_request.text_mode` 和会话中途的消息）。边界：怎么编码全在 rdaccel（1.5 的 `text_mode`，1.6 起文字块用上下文编码，都是通用的），rdmachine 只有开关、消息（`core/` 的 `picture_mode.h`）和浮窗上的一行提示。默认关：正常链路上普通模式画质更好。文字模式下客户端默认请求 1 倍的桌面（2026-11-10）：2 倍桌面的像素是 4 倍，100 kbps 上一屏文字看全要 16 秒、1 倍约 10 秒；1 倍是被控端按 1 倍渲染的文字（不是 2 倍缩小的），客户端把每个像素原样放大成 2 × 2，字比 Retina 粗糙但边缘清楚。不想要可以在菜单里关（View → Data Saver at Standard Resolution）。这只是“请求桌面”的规格不同，协议没有新东西。细节见[协议](protocol.md)的“文字模式” |
| 剪贴板 | 复制时只宣布，粘贴时才取；文件不经过剪贴板（2026-11-10） | 一复制就发会把客户端上复制的一切（别处复制的密码等）送到被控端，所以只宣布格式，对方真正粘贴时才取那一种格式；连接前就在剪贴板里的不宣布。macOS 用 `NSPasteboardItem` 的延迟提供数据：系统在主线程上要数据，读的一方能等（试过 70 秒没超时），等待时我们转主线程的事件循环，窗口不卡。文件试过两种办法都不行：延迟提供文件路径时，访达在更新“粘贴”菜单时就会读，文件在粘贴之前就传了；文件承诺（`com.apple.pasteboard.promised-file-url`）访达的粘贴不接受。所以剪贴板只共享文件名，文件以后用明确的传输窗口（类似 SFTP / NoMachine 的 Transfer a file）。rdaccel 的应用消息排在画面前面，所以大图的节奏在 rdmachine 里控制（ack 变慢或服务端跳帧就慢下来），rdaccel 不改。旧客户端拿不到承诺，服务端照旧把文本推给它；客户端不推给旧服务端。细节见[协议](protocol.md)的“剪贴板” |
| 音频 | 第一阶段不做声音 | 不采集、不传输声音，不碰两端的音量（rdaccel 的屏幕采集不收声音：macOS 13 起显式设 `capturesAudio = NO`，12.x 没有这个属性）；测试也不涉及声音 |
| 服务端界面 | 菜单栏应用，不静默运行（2026-11-09） | 菜单栏图标显示状态、配对码、指纹、权限，提供断开和设置；调试数据浮窗在客户端（远程窗口右上角，点击穿透），服务端每秒发统计过去；`--headless` 给脚本和自动测试用 |
| rdaccel 改动 | 在 rdaccel 仓库里改，边界不混 | rdaccel 只放通用的采集、编码、传输和测量（例如 `rda_host_stats` 的丢包计数）；登录、会话、界面、设置、统计的展示都在 rdmachine。rdmachine 以 submodule 固定在 rdaccel 的版本上 |
| 下一步范围 | 先做登录窗口和锁屏下的连接，再做“保持登录”；不做自动重连（2026-11-11） | lroel 定的顺序：登录窗口（含从登录窗口登录进桌面）和锁屏最重要。自动重连当时不做（3.1.0 起随“记住密码”做了，见“便捷优先”）。代价：断开时虚拟屏被拆掉，被控端的窗口挪回真实显示器，重连后再挪回来，布局可能变（程序都还在跑，不丢工作）。双因素、受信用户、用户管理、审批弹窗以后再说 |
| 守护进程和 agent | 3.0.0：拆成 LaunchDaemon + 每个图形会话一个 agent，会话随控制台迁移（2026-11-11） | lroel 要求按原计划拆，并作为大版本。守护进程（`rdmachine-server --daemon`，root，开机运行）持有端口 4100、身份和登录，按 `/dev/console` 的主人把会话交给登录窗口 agent（`--login-window`）或那个用户的 agent（菜单栏应用）；控制台换主人时在同一条控制连接上迁移会话（新消息 `session_moving` + 新的 `session_ready`），换成别人就以 `console_changed` 结束。2.3.0 的做法（两份服务端轮流监听、登录后客户端带着密码自动重连、身份复制两份）随之取消：客户端不再在内存里留密码。守护进程和 agent 之间用本机 Unix 套接字（`/var/run/rdmachine/agent.sock`，不加密），只接受代码签名和守护进程相同的 agent（audit token 核对），登录窗口 agent 必须是 root。画面端口由正在服务的 agent 自己监听（同一时刻一个），迁移时先等旧 agent 放开端口；没有做 SCM_RIGHTS 传套接字（2026-11-07 草稿里的做法），因为 4100 不是特权端口。登录规则：有人登录时只接受那个用户；在登录窗口任何账号。配对码记下用码时的控制台用户，只能迁移到登录窗口或那个用户。没有装成服务时菜单栏应用照旧独立运行。锁屏由用户 agent 处理（2026-11-11 实测），rdaccel 1.9.2 点亮关掉的显示器。还没实测：登录窗口 agent 能否拿到屏幕录制权限并采集、登录窗口下的虚拟屏（建不了就共享真实显示器、客户端缩放）。限制：开着 FileVault 时重启后停在开机解锁界面，macOS 还没启动，连不上（重启前可用 `sudo fdesetup authrestart`）。细节见[协议](protocol.md)的“守护进程和 agent”“会话迁移” |
| 从登录窗口登录 | 服务端替用户填写刚才登录 rdmachine 用的密码，不保存（2026-11-11，3.0 起由守护进程转交） | 用户在客户端输一次被控 Mac 的账号密码，守护进程用 PAM 核对后只在内存里留到第一个会话开始，随 `start_session` 交给 agent；会话开始时在登录窗口或锁屏，agent 等画面连上后填进去并回车，然后清零。迁移到登录窗口（退出登录）时不填。配对码登录不填。不做“钥匙串记住 macOS 密码” |
| 保持登录 | 放弃密钥方案，改为“记住密码”（2026-11-12，见“便捷优先”） | 原方案（钥匙串里的 P-256 密钥、挑战签名、撤销、90 天过期）不做：钥匙只能把人带到锁屏和登录窗口，越过它们还要密码，和便捷优先的原则不合；记住密码更简单，也让服务端能替用户解锁 |
| 服务和自动启动 | 参照 NoMachine：launchd 当看门狗，`rdmachine-service` 管理（2026-11-11；3.0 起加守护进程） | NoMachine 的服务端由 launchd 开机启动、崩溃后重启，用 `nxserver --install/--status/--start/--stop/--restart/--startmode` 管理。rdmachine：`org.rdmachine.daemon`（LaunchDaemon）、`org.rdmachine.server.loginwindow` 和 `org.rdmachine.server`（LaunchAgent）都是 `RunAtLoad` + `KeepAlive {SuccessfulExit = false}`：出错退出 5 秒后由 launchd 重启，菜单里的 Quit、`stop` 是正常退出，不重启。`sudo rdmachine-service install / uninstall / start / stop / restart / startmode automatic 或 manual`，`rdmachine-service status` 不用 sudo；install 立即启动守护进程，并把当前会话里手动打开的服务端换成 agent（正在进行的连接断一次）。agent 崩溃重启时会话迁移到新的 agent。同一会话里已有一份菜单栏应用在跑时，后启动的那份正常退出。安装用 pkg（2026-11-11，lroel）：DMG 拖拽写不了 `/Library/LaunchDaemons`，pkg 的 postinstall 以 root 运行 `rdmachine-service install`，preinstall 先停掉旧的；服务端、客户端是两个可选组件，不可重定位（总装到 `/Applications`）。pkg 没有签名（签它要 Developer ID Installer 证书），里面的应用保留自签证书的签名，权限不丢。`rdmachine-service` 放在服务端应用的 Resources 里。DMG 和 zip 保留给不装服务的情况 |
| 便捷优先 | 自用：登录过就可信，能进客户端电脑的人就可信，安全交给用户（2026-11-12，lroel；3.1.0） | 不做账号体系，也不加认证门槛（双因素、审批弹窗、过期、Touch ID 之类都不做）；第一次登录以后的一切为了便捷。传输加密和指纹核对保留（不影响便捷）。3.1.0 据此：①客户端第一次用密码登录成功后，把账号密码存进本机登录钥匙串（每个服务端地址一条，不弹窗问），以后每次连接自动用它登录，服务端照旧替用户填锁屏和登录窗口；被控 Mac 改了密码时问一次新的；菜单里可以“忘记已保存的密码”。取代“不做钥匙串记住 macOS 密码”。②打开客户端直接连上次那台（按住 ⌥ 打开才显示连接窗口，菜单有“连接到其他电脑…”）。③断线（网络断、画面断、服务端重启）自动在同一个窗口重连，每 3 秒一次、最多 1 分钟；被别处接管、换人登录时不重连。代价：虚拟屏会重建。④会话中途锁屏不自动解锁，只在连接、重连那一刻解。⑤服务端指纹变了时弹窗，可以一键信任新指纹（原来是直接拒绝、要手动改 known_hosts）。⑥新连接接管旧会话：同一时间第二个客户端登录后，旧连接收到 `bye`（`session_replaced`）后断开（原来回 `busy`）。⑦客户端记住远程窗口是全屏还是多大，下次按原样打开（虚拟桌面也按那个尺寸建）。⑧客户端主窗口改成连过的电脑列表（地址、账号、服务端名字、上次连接时间存在偏好设置里，密码在钥匙串）：双击直连，没存密码的弹出填好地址和账号的表单只要密码；右键编辑、忘记密码、从列表删除（连同指纹记录）；关掉远程窗口回到列表（之前回到空表单，要重输密码）。⑨服务端停了、退出了或者断网时客户端不再像卡住（2026-11-12 实际使用中报告）：心跳加快（客户端每 2 秒 ping，4 秒没消息在画面上显示“连接中断”，12 秒算断开并自动重连；服务端 5 秒 ping、15 秒放弃）；服务端停止前先发 `bye`（`server_shutdown`），菜单“断开当前连接”发 `server_disconnected`（不重连）；会话所在的服务端被主动退出时守护进程立即发 `session_moving`（`server_stopping`），5 秒内回来就接上，否则 `server_shutdown`；远程窗口中间显示状态（中断、切换桌面、重连中）和“断开”按钮。⑩客户端可以同时连多台电脑（2026-11-12）：每台一个远程窗口，各自断线重连；已有连接时再打开客户端（程序坞图标、访达、`open -n` 的第二个副本）显示列表而不是自动连接，选已经连着的那台只把它的窗口调到前面（不对同一台开第二个会话，免得自己接管自己）。⑪客户端界面重做并改成中文（2026-11-12）：列表每行一个状态色块图标、名字、状态标签（已连接 / 正在重连 / 在线 / 离线）、一行详情（地址、账号，已连接时连了多久、UDP/TCP、延迟、分辨率，否则上次连接时间和是否保存了密码）和按钮（连接 / 显示窗口）；在线与否靠客户端每 15 秒对没连着的电脑试一下 TCP 控制端口（不登录，服务端对连上就断开的对端不记日志）；新建连接表单用“密码 / 配对码”分段切换。⑫别名和分组（2026-11-12，3.2.0）：右键编辑里可以设别名（列表显示别名，服务端报的名字放在提示里）和分组；列表默认平铺，用户主动勾“按分组显示”才分组（分组按名字排、“未分组”最后、组内按最近连接）；别名和分组只存在客户端偏好设置里，重新连接时保留。配对码登录不记密码（没有密码可记） |
| 多个网络出口 | 画面走控制连接的那一对地址（2026-11-12，3.2.1） | 实际使用中报告：被控 Mac 有多个出口（比如同时有局域网和 VPN；有的 VPN 还会加第二条默认路由）时连不上：登录成功，画面不来。原因：画面 UDP 绑在所有地址上，回包源地址按路由表选，可能不是客户端发往的地址，客户端丢弃。改法放在 rdmachine：服务端自己建 UDP 套接字绑在控制连接到达的本机地址上，经 rdaccel 已有的 `rda_udp_from_fd` 交给 rdaccel（rdaccel 不改）；客户端往控制连接连上的那个 IP 发，而不是重新解析主机名（避免 IPv4/IPv6 或多地址时选到另一个）。绑定失败时退回所有地址。细节见[协议](protocol.md)的“多个网络出口” |
| 稳定性修复 | 通读代码找出的问题一次修掉（2026-11-12，3.2.2） | 不是新功能。客户端：①拖拽到画面外松手时被控端收不到松开（现在拖出画面后贴着边继续，松开照发）；②每次连接带自己的状态（`ConnectAttempt`），不再借用“新建连接”表单的字段和唯一的“正在连接”位置：重连不覆盖用户正在填的表单，也不挡住连别的电脑；重连中点“立即重试”不会在连上后把自己顶掉；③最小化的窗口照样自动重连（原来拿“窗口可见”当“窗口没关”）；④后台窗口重连成功不抢焦点、不收起列表和表单；⑤状态卡片的定时器不再让关掉的窗口和最后一帧留在内存里；⑥列表每秒查“有没有存密码”时不读密码，结果有缓存；⑦所有会话共用一个剪贴板对象，同时连两台时一台的承诺不会被另一台读走；⑧表单上的“取消”真的放弃那次连接；⑨连接超时由 rdmachine 自己控制（10 秒，原来是系统默认的一分多钟）；⑩编辑电脑不再误删密码，`host` 和 `host:4100` 算同一台。服务端：⑪输入法同步不再和结束会话抢同一把锁（会死锁，agent 挂住后每次连接都失败）；⑫守护进程等 agent 启动会话超时后让它收回，agent 收到新的启动请求时先结束手上不再被承认的会话（原来会一直 busy）；⑬菜单栏每秒的状态查询不等锁（建虚拟屏时主线程要转事件循环）；⑭代填锁屏密码前再确认一次还锁着；⑮菜单里的指纹随守护进程更新。安装：⑯升级不再用用户目录里的身份覆盖已安装的身份；⑰在登录窗口下重启服务或升级时，登录窗口 agent 用非正常退出的方式让 launchd 拉起来（这一条没法在本机验证） |
| 登录窗口的输入源 | 只选键盘布局（2026-11-12，3.2.3） | 实际使用中报告：退出登录后在登录窗口打不了字。日志显示键盘语言同步把登录窗口切到了简体拼音，打的键都进了输入法（服务端自己替用户填密码时恰好已是 ABC，所以能登录）。改为登录窗口只选键盘布局，客户端用输入法时选 ABC / U.S. / 任一 ASCII 布局；用户会话里不变 |
